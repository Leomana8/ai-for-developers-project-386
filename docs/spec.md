# Спецификация: «Календарь звонков»

Канон спецификации сервиса. Источник постановки — issue #3; все открытые решения
закрыты на wayfinder-карте #4. Термины — `GLOSSARY.md`; архитектурные решения —
`docs/adr/`.

## 1. Проблема и ценность

Сервис «Календарь звонков» — запись на звонки без переписки и согласований.
Владелец календаря публикует доступное время, Гость выбирает свободный Слот и
записывается. В проекте нет авторизации, личных кабинетов и интеграций с внешними
календарями.

## 2. Роли

- **Владелец календаря** — единственный предзаданный профиль. Создаёт Типы событий
  и просматривает предстоящие Встречи. Идентификации нет: «узнавания» Владельца не
  существует, есть просто страница Админки.
- **Гость** — без регистрации и входа. Видит Типы событий, выбирает свободный Слот
  и оформляет Запись, указав имя и email.

## 3. Домен и термины

Канонические термины — в `GLOSSARY.md`: **Гость**, **Владелец календаря**,
**Тип события**, **Окно записи**, **Слот**, **Запись**, **Встреча**, **Админка**,
**Записаться**. В интерфейсе и коде используем только их.

## 4. Функциональные требования

**Владелец календаря**

1. Быть единственным предзаданным профилем без входа в систему.
2. Создавать Тип события: название, описание, длительность в минутах.
3. Видеть список своих Типов событий.
4. Видеть предстоящие Встречи всех Типов событий в одном списке.
5. У каждой Встречи видеть имя и email Гостя, Слот и время создания Записи.
6. Видеть предстоящие Встречи в предсказуемом порядке (по времени начала).
7. Видеть понятное пустое состояние, когда Записей ещё нет.

**Гость**

8. Видеть список Типов событий (название, описание, длительность).
9. Выбрать Тип события и открыть календарь.
10. Видеть только окно ближайших 14 дней.
11. Видеть на каждом дне число свободных Слотов.
12. Видеть статус каждого Слота (свободен/занят) для выбранного дня.
13. Занятые Слоты и Слоты, не вмещающие длительность Типа события, недоступны.
14. Понимать, что занятость общая для всех Типов событий.
15. Подтвердить Запись, указав имя и email.
16. Видеть явное подтверждение успеха.
17. Иметь возможность записаться ещё после успешной Записи.
18. Видеть понятное состояние, когда на выбранный день свободных Слотов нет.
19. Видеть понятное состояние, когда Сервер недоступен.
20. Видеть ошибки валидации формы (пустое имя, некорректный email).
21. При попытке занять уже занятый Слот получать сообщение и выбор другого Слота.
22. Возвращаться к выбору дня и времени без потери контекста.
23. Пользоваться записью с телефона.

**Общие**

24. Терминология интерфейса совпадает с глоссарием.
25. Сервис работает без авторизации и внешних интеграций.
26. Публичный API живёт под `/api` и проксируется Vite.

## 5. Правила

### Тип события

| Поле | Правила |
| --- | --- |
| `id` | uuid, генерирует сервер; Владелец не вводит |
| `name` | обязательно, непустое, ≤100 символов |
| `description` | необязательно, ≤500 символов |
| `duration` | обязательно, целое число минут, кратно 15, от 15 до 90 |

- Тип события **неизменяем**: правка и удаление вне объёма. Встреча ссылается на
  `eventTypeId`; снапшот названия/длительности не хранится.
- Времени старта у Типа события нет.

### Окно записи и сетка

- **Окно записи** — 14 календарных дней, включая сегодня: `[сегодня … сегодня+13]`.
  14-й день включается целиком.
- **Рабочее окно дня** — 09:00–18:00, фиксированная константа сервера; Владелец его
  не задаёт.
- **Сетка** — единая, шаг 15 минут. Шаг старта брони — 15 минут.
- Слот стартует в отметке `t` и занимает `duration/15` подряд идущих ячеек.
- Слот, выходящий за конец рабочего окна, **не предлагается**.

### Свободный Слот и занятость

- Слот свободен, если **весь** его интервал `[t, t + duration)` лежит внутри рабочего
  окна дня и **ни одна** ячейка не занята Встречей.
- Прошедшие часы сегодняшнего дня недоступны: сегодня видны только будущие Слоты.
- Занятость **общая** для всех Типов событий: пересечение запрещено даже для разных
  типов.

### Запись

- Гость вводит **имя** (обязательно, ≤100) и **email** (обязательно, валидный формат,
  ≤254).
- Нормализация: `trim` для имени и email; email — в нижнем регистре.
- Сервер фиксирует `createdAt` (время создания Записи).
- Валидация — на клиенте (подсказка) и на сервере (`422` со списком полей).
- Кнопка отправки блокируется на время запроса; idempotency-ключа нет; гонка на один
  Слот разрешается `409`.
- **Отмена и перенос Встречи — осознанно вне объёма.**

## 6. API

Публичный API под `/api` (проксируется Vite). Время — ISO 8601 в серверной зоне
(`2026-10-10T09:00:00`); часовые пояса отложены.

| Метод | Путь | Ответ |
| --- | --- | --- |
| `GET` | `/api/event-types` | `200` `[EventType]` |
| `POST` | `/api/event-types` | `201` `EventType`; `422` |
| `GET` | `/api/event-types/:id/slots` | `200` `Availability`; `404` |
| `POST` | `/api/meetings` | `201` `Meeting`; `404` / `409` / `422` |
| `GET` | `/api/meetings` | `200` `[Meeting]` |

**EventType**

```json
{ "id": "uuid", "name": "Intro call", "description": null, "duration": 30 }
```

Тело создания: `{ "name", "description?", "duration" }` (`description` может быть `null`).

**Availability** (`GET /api/event-types/:id/slots`)

```json
{
  "eventTypeId": "uuid",
  "window": { "from": "2026-10-10", "to": "2026-10-23" },
  "days": [
    {
      "date": "2026-10-10",
      "slots": [
        { "start": "2026-10-10T09:00:00", "end": "2026-10-10T09:15:00", "available": true }
      ]
    }
  ]
}
```

Возвращаются **все** 14 дней и **все** Слоты дня с флагом `available` (и свободные,
и занятые).

**Meeting**

```json
{
  "id": "uuid",
  "eventTypeId": "uuid",
  "eventTypeName": "Intro call",
  "start": "2026-10-10T09:00:00",
  "end": "2026-10-10T09:30:00",
  "guestName": "Иван",
  "guestEmail": "ivan@example.com",
  "createdAt": "2026-10-09T18:00:00"
}
```

Тело создания Записи: `{ "eventTypeId", "start", "guestName", "guestEmail" }`.

Список предстоящих Встреч — только `start >= сейчас`, сортировка по `start` по
возрастанию; пагинация отложена.

**Ошибки** — единый конверт:

```json
{ "error": { "code": "slot_taken", "message": "Слот больше недоступен", "fields": {} } }
```

| Код | HTTP | Когда |
| --- | --- | --- |
| `validation_error` | `422` | невалидные данные (поля в `fields`) |
| `slot_taken` | `409` | Слот занят/пересекается с Встречей |
| `out_of_window` | `422` | Слот вне окна записи |
| `not_found` | `404` | Тип события не найден |

## 7. Экраны и маршруты

React Router (`createBrowserRouter`, ADR-0001).

**Гость**

| Путь | Экран |
| --- | --- |
| `/` | главная/лендинг |
| `/book` | список Типов событий |
| `/book/:eventTypeId?date=…` | календарь (окно 14 дней) и выбор Слота |
| `/book/:eventTypeId/confirm?start=…` | подтверждение (имя, email) |
| `/book/success` | успех |

**Админка**

| Путь | Экран |
| --- | --- |
| `/admin` | редирект на `/admin/meetings` |
| `/admin/meetings` | предстоящие Встречи |
| `/admin/event-types/new` | создание Типа события |

Служебные: `/health` — диагностика; `*` → редирект на `/`.

**Главная** — синтез: hero (ценность, CTA, бейдж) + блок «Что доступно прямо сейчас»
со списком Типов событий из `GET /api/event-types` + «Как это работает» (3 шага) +
футер. Клик по Типу события → `/book/:eventTypeId`; CTA «Записаться» → `/book`.

**Состояние потока** живёт в URL (`eventTypeId`, `date`, `start`); подтверждение и
успех — отдельные маршруты. Календарь: `availability: loading | error | ready`,
`selectedDate`, `selectedSlot`. Подтверждение: `form` + `submission:
idle | submitting | error`; `409` → сообщение и возврат в календарь с обновлением;
`422` → ошибки полей. Смена Типа события или дня пересчитывает сетку и сбрасывает
выбранный Слот.

## 8. Тесты

Два существующих шва, новых не заводим; хранилище не вскрываем.

- **Сервер** — интеграционные через `createApp()` + реальный HTTP `fetch`.
- **Веб** — компонентные под `MemoryRouter` + `@testing-library/react`; граница
  `/api` (`fetch`) мокается.

**Обязательное покрытие:** занятость и окно (нельзя занять занятое/вне окна);
гостевой поток от выбора Типа события до успеха; создание Типа события; список
предстоящих Встреч; валидация формы; обработка `409`.

**Ошибки в UI:** Сервер недоступен → «Записаться сейчас нельзя, попробуйте позже»;
`409` → «Слот больше недоступен» + обновление сетки; `422` → ошибки полей.

**Пустые состояния:** нет Типов событий → «Пока нет доступных типов»; нет свободных
Слотов на день → «На этот день нет свободных слотов»; нет предстоящих Встреч →
«Пока нет записей».

## 9. Вне объёма

- Авторизация, личные кабинеты (ADR-0002).
- Интеграции с внешними календарями (ADR-0002).
- Реальная отправка email и уведомлений.
- Мультивладельцы и несколько календарей (Владелец один, предзаданный).
- Отмена и перенос Встречи.

## 10. Открытые вопросы

- Копирайт и визуальные детали (адаптив, бренд-цвет из референса, тема shadcn).
- Клиентская vs серверная валидация в деталях.
- Сортировка и пагинация списка предстоящих Встреч.
- Часовые пояса.
